## 1. 🚨 オーナーの生体認証が使えなくなった（発生・原因特定・復旧すべて当日）

**現場**: `www.shiftlink-app.jp`（SaaSモード・オーナー）。「生体認証が出ない」。

### 原因
**8/5に「持ち主のいないパスキー」を掃除したとき、オーナー分を巻き込んで消していた。**
オーナーは内部的に `cast_id=0` で、`casts` に id=0 の行は存在しない。
そのため `WHERE cast_id NOT IN (SELECT id FROM casts)` 型の掃除で道連れになる。

さらに端末側の目印 `localStorage['pkv2_0']` が残っていたため、

| | 結果 |
|---|---|
| ログイン | サーバーに鍵が無い → 黙って失敗（生体認証が出ない） |
| 登録案内 | 目印があるので「登録済み」と判断されて出ない |

＝ **ログインも登録もできない行き止まり。**

### 直したもの（3つ）
| # | 内容 | 反映 |
|---|---|---|
| 1 | サーバーが「登録なし」と答えたら端末の目印を捨てる（自己修復） | `2847354` |
| 2 | 管理→端末の管理に**「この端末で生体認証を登録」ボタン**を追加 | `4c64a7d` |
| 3 | `allowCredentials` を `internal` に絞り、**QR（別端末で認証）を出さない** | `8f2e01b` |

**復旧確認済み**: オーナーの登録端末数 `0 → 2`（PC・スマホ）。

### 🚨 再発防止
**cast_id を持つ表の掃除SQLには必ず `AND cast_id <> 0` を入れる。**
`passkeys` / `auth_pins` / `push_subscriptions` すべてに同じ罠がある。

## 2. LPアナリティクスのリセットと、2つのバグ修正（`cf507d2`）

### リセット
`lp_analytics_events` の **1187行を全消し**（今野さんがSQL Editorで実行）。
内訳は `section_view 814 / pageview 200 / dwell 153 / cta_click 17 / conversion 3`。
**7/28・7/29・8/5（作業日）だけで95%** ＝ ほぼ自分のテストだった。本物の外部訪問は9PV。

### 🐛 バグ①: 1000行で静かに過少集計
集計関数が件数上限を指定しておらず、Supabaseが既定の1000行で打ち切っていた。
**エラーにならず少ない数字が出るだけ**なので気づけない（実測 `pageview 200→173`）。
→ `.range()` で最後まで読む。`.order('id')` で並び順を固定（ページ境界の重複・欠落防止）。

### 🔧 バグ②: 身内のアクセスが混ざる
→ 本番ドメイン以外では計測しない ＋ **`?notrack=1` を開いた端末は以後対象外**。
早期returnで `lp_sid` 付与も止まるため、身内のテスト申込が `conversion` に混ざらない。

**運用**: 今野さんのスマホ・PCで `https://lp.shiftlink-app.jp/?notrack=1` を1回ずつ実施済み。
**検証済み**: 除外される／本物の訪問は記録される の**両方向**を実測。
