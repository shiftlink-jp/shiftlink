# メール送信の設定手順（所要：約40分／うち待ち時間30分）

作成 2026-08-06。**今野さんの操作が必要な作業**です。Claudeだけでは完了できません
（Resendのアカウント作成・DNSの変更・Supabase管理画面への入力は、いずれも本人操作が要るため）。

---

## 1. なぜ必要か（先に読むところ）

いまShiftLinkは**メールを1通も送れません**。「設定が甘い」のではなく、**構造的に送れない**状態です。

Supabaseには最初から簡易のメール送信機能が付いていますが、これは開発中のお試し用で、

- **1時間に2通まで**（プロジェクト全体で。1人あたりではない）
- **プロジェクトのメンバー以外のアドレスには、送信を拒否する**

という制限があります。2つ目が致命的で、**お客さん（店舗オーナー）のアドレスには最初から届きません**。
（出典は末尾）

### 具体的に何が困るか

| 場面 | いまどうなるか |
|---|---|
| オーナーがパスワードを忘れた | **再設定メールが届かない＝二度とログインできない** |
| メールアドレスを変更したい | 確認メールが届かず変更できない |
| 領収書・お知らせを送りたい | そもそも送れない |

いちばん怖いのは1行目です。**実店舗が使い始めた後にこれが起きると、こちらから復旧する手段がありません。**
だから「実店舗が増える前に必ず終わらせる」タスクとして挙げていました。

---

## 2. どうやって直すか

「独自SMTP（どくじエスエムティーピー）」を設定します。
**SMTP = メールを送るための郵便局**のことです。Supabaseの貧弱な郵便局をやめて、
ちゃんとした郵便局に切り替える、という作業です。

郵便局には2つの候補があります。

### 案A：Resend（推奨）

メール配信の専門サービス。**月3,000通まで無料**。ShiftLinkの規模なら当面ずっと無料です。

- ✅ 迷惑メールに入りにくい（届く確率が高い）
- ✅ 送ったメールが届いたか、管理画面で1通ずつ追える
- ❌ 新しくアカウントを作る必要がある
- ❌ DNS（ドメインの設定）に3〜4行の追記が必要

### 案B：エックスサーバーのメール

`shiftlink.jp` は既にエックスサーバーで動いており、メール送信の設定（SPF）も入っています。
そこのメールアドレスをそのまま郵便局として使う手もあります。

- ✅ 新しいアカウント登録が不要。すぐ終わる
- ❌ 大量に送ると制限がかかる（システムメール向けの設計ではない）
- ❌ 届いたかどうかを追えない

### 💡 おすすめ

**案A（Resend）**です。理由は、パスワード再設定メールは「届かなかったら詰む」種類のメールで、
**届いたかどうかを確認できること**に価値があるからです。案Bだと「送ったつもりで届いていない」を
検知できず、お客さんから「メールが来ません」と言われて初めて気づくことになります。

以下は案Aの手順です。

## 3. 手順（案A：Resend）

### ステップ1：Resendに登録（5分）

1. https://resend.com/signup を開く
2. メールアドレスとパスワードで登録（GitHubアカウントでも可）
3. 支払い情報の入力は**不要**。無料枠のまま進む

### ステップ2：ドメインを追加（3分）

1. 左メニュー **Domains** → **Add Domain**
2. ドメイン名に **`shiftlink-app.jp`** と入力
   （アプリの公開URLと揃えるため。`shiftlink.jp` ではなくこちら）
3. Region は **Tokyo (ap-northeast-1)** を選ぶ
4. 追加すると、**Records（DNSレコード）の一覧**が表示される。この画面は開いたままにする

> レコードの値は**ドメインごとに毎回変わる**ので、この手順書には書けません。
> Resendの画面に出た値を、そのままコピーして使ってください。

### ステップ3：DNSに登録（10分＋待ち30分）

`shiftlink-app.jp` のDNSは**エックスドメイン**で管理されています
（確認済み：ネームサーバーが `ns1〜3.xdomain.ne.jp`）。

1. https://www.xdomain.ne.jp/ にログイン
2. **ドメイン管理** → `shiftlink-app.jp` → **DNSレコード設定**
3. Resendの画面に出ている行を、**1行ずつそのまま**追加する
   - 種別が **TXT** のもの（SPF・DKIM＝「なりすましではない」ことの証明）
   - 種別が **MX** のもの（送信元の応答用）
4. 追加したら **Resendの画面に戻って「Verify DNS Records」を押す**

> ⚠️ 反映に**最大30分ほどかかります**。押してすぐ「Pending」でも異常ではありません。
> 30分後にもう一度押して、**すべて緑の「Verified」**になればOKです。
>
> ⚠️ ホスト名の入力形式に注意。Resendは `send.shiftlink-app.jp` のようにドメイン込みで表示しますが、
> エックスドメインの入力欄は**ドメインを除いた部分だけ**（この例なら `send`）を求める場合があります。
> 入力欄の下の説明を必ず確認してください。**ここを間違えるのが一番よくある失敗です。**

### ステップ4：APIキーを作る（2分）

1. Resendの左メニュー **API Keys** → **Create API Key**
2. 名前は `supabase-production` など分かるものに
3. Permission は **Sending access** を選ぶ
4. 作成すると `re_` で始まる文字列が出る。**この画面を閉じると二度と見られない**ので、
   その場でコピーして安全な場所（パスワード管理アプリ等）に保存する

### ステップ5：Supabaseに入力（5分）

**★本番プロジェクトは `qgcgkrcrfzonmmygcdju` です。**
（`fewuonnrgqnxtopkjudt` は開発用。間違えると設定しても何も変わりません）

https://supabase.com/dashboard/project/qgcgkrcrfzonmmygcdju/settings/auth

→ ページ内の **SMTP Settings** を探し、**Enable Custom SMTP** をONにして以下を入力：

| 項目 | 入れる値 |
|---|---|
| Sender email | `noreply@shiftlink-app.jp` |
| Sender name | `ShiftLink` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` （←この6文字をそのまま。アドレスではない） |
| Password | ステップ4でコピーした `re_` で始まるキー |

**Save** を押す。

### ステップ6：送信上限を上げる（1分）

独自SMTPを入れた直後は「1時間30通」の制限がかかります。少なすぎはしませんが、
念のため確認しておきます。

https://supabase.com/dashboard/project/qgcgkrcrfzonmmygcdju/auth/rate-limits

→ **Rate limit for sending emails** を確認。30のままでも当面問題ありません。

## 4. 動作確認（必ずやる）

設定しただけでは終わりです。**実際に届くかを確認してください。**

1. https://shiftlink-app.jp/ を開く
2. ログイン画面の「パスワードをお忘れですか」から、**今野さんご自身のアドレス**で再設定を要求
3. **1〜2分以内にメールが届けば成功**

### 届かないとき

| 症状 | 原因と対処 |
|---|---|
| 迷惑メールフォルダに入っていた | DNSは正しい。少し使えば改善する。まずは受信トレイに移動 |
| まったく届かない | ResendのDomainsが全部「Verified」か確認。1つでも赤ければDNSの入力ミス |
| Resendの管理画面にも記録がない | Supabase側の入力ミス。Usernameが `resend` になっているか（アドレスを入れていないか）確認 |

Resendの **Emails** 画面を見れば、送信を試みた記録が1通ずつ残ります。
「Supabaseから出ていないのか」「出たけど届いていないのか」がここで切り分けられます。
